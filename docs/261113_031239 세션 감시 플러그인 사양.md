# 세션 감시 플러그인 사양 (paseo-session-watch)

## 목적

Paseo에서 돌아가는 에이전트 세션을 결정론적으로 감시한다.

- 선택한 세션들이 모두 끝나면 PC를 종료한다.
- 세션이 끝난 뒤 후속 작업(같은 세션에 메시지, 새 세션 생성)을 의존 관계에 따라 실행한다.
- 토큰 한도로 끊긴 세션은 할당량이 초기화될 때까지 기다렸다가 `continue`로 재개한다. 반복한다.

## 확정된 정책

| 항목 | 결정 |
|---|---|
| 한도가 아닌 실패·취소 | 그 작업은 `failed`로 종결. 종료 조건에 포함. 그 작업에 의존하는 후속 작업은 `skipped` |
| 권한 요청 대기 | 대기가 설정 시간(기본 30분)을 넘으면 `failed`로 종결 |
| 후속 작업 표현 | 작업 노드 + `after`(선행 노드 목록) 의존 그래프 |
| 종료 방식 | `shutdown /s /t 60`. 60초 안에 GUI 또는 `shutdown /a`로 취소 |
| 재개 메시지 | 기본 `continue`. 계획마다 변경 가능 |

## 실행 위치와 결정성

- 모든 판단은 데몬 쪽 서버 엔트리(`index.server.ts`)가 한다. 앱이 꺼져 있어도 동작한다.
- 계획 상태는 `~/.paseo/plugin-data/paseo-session-watch/plan.json`에 저장한다. 플러그인이나 데몬이 재시작되면 이어서 진행한다.
- 상태 변경은 하나의 직렬 큐에서만 일어난다. 훅과 주기 점검이 동시에 상태를 건드리지 않는다.
- 신호원은 두 가지다.
  - `agent.turn.after` 훅: 빠른 반응. 전달이 보장되지 않는다.
  - 30초 주기 점검: 에이전트 스냅샷을 다시 읽어 놓친 종료와 권한 대기를 맞춘다.

## 데이터 모델

```
Plan  { id, status: active | shutting_down | finished | canceled,
        shutdown: boolean, resumeMessage, permissionTimeoutMin,
        nodes: Node[], log[], shutdownAt? }
Node  { id, kind: watch | send | create, after: nodeId[],
        target (send): { agentId } | { nodeId },
        create: { cwd, provider("provider/model"), modeId?, title?, prompt },
        text (send),
        agentId?, state: pending | running | waiting_quota | done | failed | skipped,
        startedAt?, quotaUntil?, limitHits, pendingPermissionSince?, note? }
```

- `send` 노드는 같은 에이전트를 대상으로 하는 앞선 노드들에 자동으로 의존한다. 한 에이전트에 턴이 겹치지 않는다.
- `watch` 노드는 계획 시작 시 에이전트가 실행 중이면 `running`, 이미 멈춰 있으면 마지막 응답으로 판정한다. 한도 문구면 `waiting_quota`, 아니면 `done`.

## 노드 상태 머신

```
pending ──선행 모두 done──▶ 실행(send/create) ──▶ running
pending ──선행 중 failed/skipped──▶ skipped
running ──턴 종료: 완료──▶ done
running ──턴 종료: 한도──▶ waiting_quota(quotaUntil)
running ──턴 종료: 실패/취소──▶ failed
running ──권한 대기 > 제한──▶ failed
waiting_quota ──quotaUntil 도달 + 사용량 확인──▶ resumeMessage 전송 ──▶ running
```

계획: 모든 노드가 `done | failed | skipped`이면 `shutdown`이 켜진 경우 종료를 예약하고 `shutting_down`, 아니면 `finished`.

## 종료 판정 강화 (settling 단계)

실험으로 확인한 사실(Paseo 0.15.4, Claude):

- 메인 턴이 끝나면 백그라운드 서브에이전트·백그라운드 셸이 남아 있어도 Paseo는 `idle`, `attentionReason: finished`로 표시한다.
- 백그라운드 작업이 끝나거나 중간 보고하면 Claude가 스스로 깨어나 자율 턴(`turn.before`/`turn.after` 훅 발생)을 연다. 그 사이 `idle` 구간이 1분 가까이 이어질 수 있다.
- 타임라인의 백그라운드 `Agent`·`Bash` 도구 호출은 띄우는 즉시 `completed`라서 남은 작업을 알 수 없다. 서브에이전트 완료 알림은 타임라인에 오지 않는다.
- Claude 세션 기록(`~/.claude/projects/*/<sessionId>.jsonl`)에는 백그라운드 시작(`toolUseResult.backgroundTaskId`, `status: async_launched` + `agentId`)과 완료 알림(`<task-notification>`의 `task-id`)이 모두 남는다. 중간 알림에는 "may be interim" 문구가 붙는다.
- 에이전트가 만든 Paseo 에이전트에는 `paseo.parent-agent-id` 라벨이 붙는다.

규칙: 턴이 완료로 끝나면 `done`이 아니라 `settling`이 된다. 아래가 모두 `quietMin`(기본 3분) 동안 유지되면 `done`.

1. 상태가 `running`/`initializing`이 아니고 권한 대기가 없다. 아니면 `running`으로 되돌림.
2. 새 턴 시작 훅이 없다. 있으면 `running`으로 되돌림.
3. 스냅샷 `updatedAt`이 바뀌지 않는다.
4. Claude 세션 기록상 최종 완료 알림이 없는 백그라운드 작업이 없다. `backgroundMaxMin`(기본 240분)을 넘긴 작업은 무시하고, 그 시점부터 조용한 시간을 센다.
5. 하위 Paseo 에이전트(라벨 기준, 재귀)가 실행 중이거나 권한 대기 중이 아니다.

## 한도 초과 판정 (조사 결과)

Paseo 0.15.4 데몬 코드를 직접 확인한 결과다.

- **Claude**: Paseo는 SDK `result`의 `subtype === "success"`면 `is_error`와 무관하게 `turn_completed`로 처리한다. 그래서 한도 초과는 정상 완료처럼 오고, 마지막 assistant 메시지에 한도 문구가 남는다. Claude Code가 한도 문구로 분류하는 접두어는 `You've hit your`, `You've reached your`, `You're out of usage credits`, `You're out of extra usage` 등이다. 성공이 아닌 `result`는 `errors[]`를 합쳐 `turn_failed`로 만든다.
- **Codex**: 턴 상태가 `failed`면 `turn_failed`가 되고 원문 메시지(`You've hit your usage limit ...`)가 `error`에 담긴다.
- Paseo는 Claude의 `rate_limit_event`(구조화된 `resetsAt`)를 플러그인에 노출하지 않는다.

판정 규칙:

1. 턴이 `failed`이고 메시지가 한도 패턴과 일치하면 한도.
2. 턴이 `completed`라도 마지막 assistant 메시지가 짧고(500자 이하) 한도 접두어로 시작하면 한도.
3. 그 외 `failed`/`canceled`는 실패, `completed`는 완료.

## 대기 시각 결정

1. `paseo.providers.listUsage()`에서 해당 프로바이더의 사용량 구간 중 소진된 것(`remainingPct <= 0` 또는 `usedPct >= 100`)의 `resetsAt` 최댓값.
2. 없으면 메시지 문구 파싱(`try again in 2 hours 3 minutes` 형식).
3. 둘 다 없으면 30분 후 다시 확인.
4. 대기 시각에 2분 여유를 더한다. 시각이 되면 사용량을 다시 확인하고, 아직 소진 상태면 다시 대기한다.
5. 재개 직후 5분 안에 다시 한도에 걸리면 최소 15분을 기다린다. 한 노드의 한도 재시도는 최대 50회.

## GUI

- 사이드바 항목에서 화면을 연다.
- 계획이 없으면 편집기를 보여준다.
  - 세션 목록(보관되지 않은 것)에서 여러 개를 골라 감시 노드로 만든다.
  - 후속 작업 추가: 종류(메시지/새 세션), 선행 노드, 대상, 내용.
  - 옵션: PC 종료 여부, 재개 메시지, 권한 대기 제한.
- 계획이 있으면 노드별 상태, 대기 시각, 로그, 계획 취소, 종료 취소 버튼을 보여준다.

## 남은 위험

- Claude 한도 메시지가 타임라인에 assistant 메시지로 남는지는 실제 한도 상황에서 확인해야 한다. 판정에 실패한 종료는 로그에 원문을 남겨 패턴을 보강한다.
- 사용량 보고서는 5분 캐시라서 약간 늦을 수 있다. 여유 시간과 재확인으로 흡수한다.
